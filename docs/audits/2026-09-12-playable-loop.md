# P2/P3 最小可玩流程与画面修正

本批实现[实施计划](../12-implementation-roadmap.md)的 P2/P3：真实客户端经 TLS 登录选角，在原始地图移动遇敌、手动战斗/捕获，获得奖励后保存退出，重登和服务端重启后继续读取同一份进度。启动方法见[部署说明](../../deploy/README.md)。

## 实现与依据

- `session_storage` 使用 MySQL 8.4.8、Connector/C++ 8.4 JDBC/classic 和 Redis 8.6.2。角色、宠物、道具在同一事务保存；运行时句柄不入库，资产使用稳定 UID，revision 拒绝旧版本覆盖。Redis token 校验与 SQL 会话栅栏共同约束存档归属。
- IDL `persisted` 描述生成字段 visitor，`shared/data` 据此编码带 `schema_ver` 的 JSON，64 位标识符使用十进制字符串。UTF-8、数值范围、重复槽位和资产归属均有检查。
- TLS 位于 `runtime/tls`，使用 memory BIO 接入两端现有非阻塞 TCP，验证 CA 和主机名，最低 TLS 1.2。OpenSSL 依赖留在宿主层；L3 规则保持标准库依赖。
- 创建角色按 `StoneAge/gmsv/src/char/char.c:94–178` 核对：四维总计 20、元素总计 10、相克元素不能共存，初始等级 1、魅力 60、MP 100；image 100000 与 face 30000 的对应关系来自原版角色图号检查。
- `GameScene` 提供登录/注册、选角/创建、地图、目标选择、攻击/捕获/防御/逃跑、首只宠物参战、宠物/背包和保存退出。旧 demo 入口保留；可玩入口使用实际角色属性与权威战斗事件。
- 保存失败时保留实体；断线和停服等待存档请求完成。重复发送移动请求不能重置 250ms 移动间隔。客户端的连续战斗、登录重试和异步回包关联均有回归覆盖。

## 内容切片与方向修正

内容版本为 `p2-b934dc8a501ca820ad40282a649120f7`：赛伊那斯 floor 100，800×800，测试入口 `(643,459)`；真实遇敌区 21，group 88/89/91/92/1230。周年组 1230 的道具 1961 门控保留。共 **3,910 张图元、9 张图集、8 种角色/敌人动画**，使用原始 PALET_1，记录全部 16 张调色板、来源和产物 SHA-256。

显示取客户端 `.dat` 的 L0/L1，通行性取服务端 LS2MAP 与 mapset。两套源文件地面层有 321,681 格差异，物件层有 134 格差异，已写入 manifest；本批未宣称所有地图版本已统一。原版源码及程序仅作静态资料读取，未运行或编译。

用户指出图像上下颠倒后，沿原始客户端源码核实并修正：

| 问题 | 依据与处理 |
|---|---|
| 贴图上下颠倒、UI 正常 | `sprmgr.cpp` 从 `bmpHeight-1` 开始，`directdraw.cpp` 每行减去源宽度。REAL 是 bottom-up，PNG 是 top-down；逐张图元倒序读取扫描线，保持 ADRN 偏移。UI 使用独立绘制流程，因此未受影响 |
| 红底“部件”标记被显示 | `anim_tbl.h` 定义 `CG_INVISIBLE=99`，`map.cpp` 仅绘制大于 99 的图号；0–99 即使存在 ADRN 调试图也不绘制 |
| 地图坐标和动画方向不一致 | 投影改为 `(x+y)*32,(-x+y)*24`；服务端方向按 `netproc.cpp` 的 `(dir+3)%8` 转换为动画方向 |
| 战斗双方位置相反 | 按用户明确要求，敌方在左上、朝向右下（SPR 7），我方在右下、朝向左上（SPR 3）；目标按钮与名字位置同步 |
| 目标点击偶尔失效 | 目标按钮移出每个动画帧的重建过程，按 UI 状态更新；捕获结果不再被每回合自我信息覆盖 |

扫描线与隐藏标记已加入常驻 `playable_content` 检查。上游[资源取证文档](../../../stoneage-plan/docs/03-assets.md)与抽样 PNG 导出器同步更正。

## 当前边界

这是单地图可玩闭环。完整出生村/初始宠物流程、升级、死亡回城与恢复、跨图、完整技能、装备和经济社交仍按后续范围推进。掉落当前保留物品 ID 与叠数，尚未导入完整道具定义；名称缺失时 UI 显示“战利品”。调色板采用静态 PALET_1，未实现昼夜变化。

当前只验证了 macOS 的真实图形操作；三平台无引擎构建不能代表 Windows/Linux 图形端验收。数据库 COMMIT 回执丢失后的自动核对、连接故障恢复及更大规模压力验证仍需独立批次，本批不将这些能力计为完成。
