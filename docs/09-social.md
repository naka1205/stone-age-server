## 3. 家族操作与一致性

### 3.1 ★ 42 条协议全部只改内存 + 脏标记

`17` §5.8:建族 / 入族 / 退族 / 解散 / 改资料 / 设点 / 结算 / 写公告 ——
**全部只改进程内存结构并置脏标记**,真正落盘要等周期任务,间隔 **600 秒**。

**失败后果**:存储服务崩溃 ⇒ 最多 10 分钟内的全部家族操作回滚,
而**角色存档里已经写了新的家族字段** ⇒

- **孤儿成员**(角色以为自己在家族里,家族名册里没有);
- **幽灵家族**(家族存在,成员的角色档不认)。

### 3.2 ★★ 锁根本不覆盖家族

`17` §6.3 —— **最关键的一条**:

```
账号锁:纯进程内存 256 桶哈希链,零持久化
★ 粒度只有账号级 ⇒ 没有角色级、道具级、家族级锁
⇒ 42 条家族协议完全无保护,靠「存储服务单线程」隐式串行化
```

⇒ ★★ **拆分后若家族服务变成多实例/多线程,这个隐式保证立刻失效。**

**新实现必须显式补的**:

| # | 今天靠什么 | 拆开后必须有 |
|---|---|---|
| 1 | 单线程 ⇒ 42 条协议天然串行 | ★ **家族级并发控制** |
| 2 | 单 TCP 长连接 ⇒ 应答按序返回 | 72 条的显式 `request_id` |
| 3 | 同一进程 ⇒ 锁与存档在同一内存 | 分布式锁 + 锁与存档的原子提交 |
| 4 | 同一次文件写 ⇒ 一个文件一次写完 | 事务或幂等重试 |
| 5 | 两侧同生共死 | 实例世代号 |

### 3.3 四个必须原子的家族操作

`04-storage-schema.md` §5 的 T8–T11,此处补语义:

| 操作 | 涉及状态 | 中途失败 |
|---|---|---|
| 家族仓库 / 资金 | 内存结构 + 落盘 | 回滚 10 分钟 |
| 建族 / 入族 / 退族 / 解散 | 家族结构 + 成员表 + **角色存档的家族字段(另一侧)** | ★ **孤儿成员 / 幽灵家族** |
| 庄园占领结算 | 庄园表 + 双方家族点数 + 公告 | 归属与点数不匹配 |
| 家族 PK 结算 | 胜方 + 败方 | ★ **战绩单边** |

⚠️ 前两项**跨两个服务** ⇒ Saga;后两项同在社交侧 ⇒ 单库事务。

## 5. 聊天与频道

### 5.1 ★ 频道类广播是全扫,不是订阅

`15` §7.3:**除地图局部广播外,频道类广播都是「全扫连接表」而非订阅制。**

| 扇出 | 维度 | 说明 |
|---|---|---|
| **职业频道** | `fdnum` × (职业数−1) | ★ 按连接数动态分配,**发言时全扫** |
| **家族频道** | 1000 × 5 × 50 | 静态表(§2.2) |
| 全服公告 | 连接表全长 | GM 命令与循环公告 |

⇒ ★ **新实现引入订阅/房间模型是直接收益,且不改变玩法语义。**

### 5.2 新形状

```
Channel        = { kind, key }        // kind: WORLD / FAMILY / PARTY / PROFESSION / ROOM
Subscription   = (entity, channel)    // ★ Redis 集合 / 进程内订阅表
publish(channel, msg) → 只投递给订阅者
```

★ **地图局部广播保持不变** —— 它本来就是按视野格扫的(`10-world-map.md` §5),
不是频道。

### 5.3 ★ 跨线路聊天室是拓扑的一部分

`17` §0.3 面 ①:8.0 有一条**跨线路聊天室**协议(506 行实现),**8.5 已整体删除**。

★ **在分布式部署下它不是玩法长尾,而是跨分片通信面的现成设计** ⇒ **进第一批**。

⚠️ 与它同族的还有 **12 条全服扇出协议**(`17` §8.4)——
全服喊话/上下线、天气特效、跨线路私信 ×3、跨线路踢人与在线查询 ×3、石碑排行 ×2、跨线路聊天室。

⇒ ★ **这 12 条 + 42 条家族协议 = 多线路一致性的全部入口。其余都是"单线路 × 单账号",天然可分片。**

### 5.4 循环公告:一个会被基础设施迁移顺手丢掉的子系统

`16` §7.4:

| 项 | 事实 |
|---|---|
| 计时器 | 每 10 秒一跳;触发条件 `> 60 × 公告间隔` |
| 扇出 | 遍历全部玩家,每人两条(服务器名 + 正文),轮播 |
| 装载 | **上限 10 条 × 1024 B** |
| 配置 | 公告文件路径 + 间隔(默认 10 分钟) |
| B80 | ★ **5/5 getter 命中**,两个配置键都在二进制配置表内 ⇒ **8.0 有** |
| ⚠️ 投产实态 | `loopannounce.txt` **只有 1 字节** ⇒ **机制在、内容空** |

⚠️ ★★ **它的实现位置在网络层文件里,而该文件属"已弃用基础设施"**
⇒ **按现有计划迁移会连带丢掉这个玩法子系统。**

★ **「是子系统,但不是玩法内容」** —— D8 裁定为**长尾**:机制要有(运营需要),内容从零开始配。

## 8. GM 命令体系

> **为什么放在本文**:原版 GM 命令**从聊天通道进来**,与聊天派发在同一个文件。
> ⇒ **必须一起裁定,且必须一起改。**

### 8.1 清单口径:8.0 是 123 条

```
原码表条目(含被宏门控的)         135
减去 8.5 宏表为「关」的 4 条
8.5 生效条目                       131      ← 源码 132 行,有一条整行被注释
减去 11 条 B80 无符号(8.5 新增)
★ 补回  3 条视图误删(8.0 有 · 8.5 关)
★ 8.0 实证存在的 GM 命令           123
```

★ **须补回的 3 条**(方向 B:8.5 关 · 8.0 有):GM 道具功能、设定骑宠、移动骑宠。

★ **可扣掉的 11 条里,最后 4 条全是 Lua 相关** —— 与"8.0 无 Lua"的结论**独立互证**。

**等级分布**(131 条口径):L1 = 7 / L2 = 64 / L3 = 60。

### 8.2 ★★ 权限模型:五条机制,含一个运营级后门

| # | 机制 | 风险 |
|---|---|---|
| ① | 等级来源 = 配置文件或运行期注入 | `csa8.0` 的配置里**只有一个 GM 账号** |
| ② | ★★ **校验开关 ≠ 1 ⇒ 任何玩家 GM 等级直接置 3** | ⚠️ **运营级后门。新实现不应保留。** |
| ③ | 等级不足即**静默拒绝**(无提示、无日志) | 排障困难 |
| ④ | 通过后**必记日志**(名字/账号/原文/坐标) | ✅ 审计到位 |
| ⑤ | ★ **权限表不是编译期常量** —— 有命令可运行期改写等级 | 等级可被在线篡改 |

⚠️ ★ **② 是最严重的一条**:如果校验开关没开到 1,**全服玩家都是 GM 3 级**。
`csa8.0` 是否开着**取决于运行期配置,静态不可判定**。

⇒ ★★ **对新架构的硬要求**:
**GM 权限必须是独立的鉴权面,不能与聊天通道复用,更不能有"校验没开就全放行"的 fail-open 语义。**

### 8.3 非命令表的地图编辑函数

7 个不走命令表前缀的函数(在线改 tile / obj / 存图 / 删图 / 打印计数),
其中 1 个**整行被注释** ⇒ **实际生效 6 个**。

★ 前 5 个是**在线地图编辑器**。⇒ 这解释了为什么那个 6,354 行的文件**零魔法逻辑**:
它是"123 条 GM 命令 + 6 个地图编辑函数"。

### 8.4 新形状

```
GM 面走独立端口 / 独立鉴权,不复用玩家会话
命令定义 = 数据(名称 / 参数 schema / 最低等级 / 是否需二次确认)
执行结果 = 结构化审计事件(★ 拒绝也要记,原版拒绝是静默的)
```

⚠️ **`00` §8 已裁定不做 Web 后台** ⇒ **GM 能力先走游戏内命令通道**,
但**鉴权面必须独立**。后果要认下:运营与排查全靠日志与指标。
