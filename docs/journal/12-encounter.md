#### ① ⚠️★★ 第一件事就走错了文件 —— `enemy1.txt` 不是 `enemy.txt`,而且错得"完全合理"

M.4b 与本批开工时的记载(含 §9.0.33 ⑤ / §9.0.34 ⑥ / `Enemy.h`)一律把遇敌表写作
**`enemy.txt`**。实测:`setup.cf` 的 `enemyfile` 指向 **`enemy1.txt`(34 列 / 2154 行)**,
而 `enemy.txt`(33 列 / 1494 行)是**宏关闭时代的旧数据**。
判据 = `ENEMY_STARTINTNUM` 在 `_BATTLENPC_WARP_PLAYER` 开时是 **4**(`char/enemy.c:458`),
该宏 `include/version.h:103` **已定义** ⇒ 多一列 `ENEMY_ACT_CONDITION`。

★★ **危险的地方在于走错文件不会报错,只会给出一整套自洽的错结论**:
两个文件的 int 列**整体错位一位**,而每一列都还是合法整数。
⇒ 我先按 `enemy.txt` 量过一遍等级分布,得到「`lv_min > lv_max` 占 **60%**」——
数字看起来完全合理(还顺手推出「min/max 交换是主路径」这个结论);
换成 `enemy1.txt` 重量,**那 60% 变成 0%**,结论整个反过来。

⇒ ★ 这是 `stoneage-plan/docs/05` §3.1「同目录新旧两版数据文件 = 宏状态的天然标尺」
第一次在实现侧兑现,而兑现方式是**先踩一遍**。
⇒ **口径更正(不回改历史节,在此声明)**:此后一律写 `enemy1.txt`;
`01` §13 与 `world/Api.h` / `Enemy.h` 的措辞已同步改正,§9.0.33/34 作为历史记录保留原文。

#### ② 裁定:等级两支**都是原版**,而分流靠一个局部变量的初值

`ENEMY_createEnemy:1030-1035` = `baselevel > 0 ? baselevel : RAND(LV_MIN, LV_MAX)`。
⇒ M.4b 的「等级是入参」**不是权宜,它就是前一支**。

★ 而"谁决定等级"在源码里**不是一个显式的参数选择**:
`battle.c:2178` 声明 `baselevel = 0`,**只有 NPC 触发那一支赋值**(`:2225` 取 NPC 等级),
两支统一传入(`:2250`)⇒ 野外遇敌(`:2228` 的 `npcindex == -1`)一路保持 0 ⇒ 走摇号。
⚠️ **只读 `ENEMY_createEnemy` 看不出这件事**,必须回到调用方 —— 这也是本批把
「`baselevel <= 0` 就摇号」而不是「另开一个函数」的理由:调用方本来就按这个条件分流。

#### ③ ★★ 载入期两条归一:实测**一次都不触发**,仍然移植 —— 判据不是"照抄源码"

源码 `:479-486`(载入期,写回表):`if(lv_min==0) lv_min=lv_max;` + `min/max` 互换。
实测 `enemy1.txt` 2154 行:`lv_min == 0` **0 行** · `lv_min > lv_max` **0 行**。

★ **移植的判据是第三条,前两条都不够硬**:`Rules::Random::rand` 的接口契约写明
「`lo > hi` 的行为由实现定义,**调用方须自行保证** `lo <= hi`」——
原版靠载入期归一满足这个前提 ⇒ 不移植就是把一个**原版永不出现的状态**
引进自己的运行期。⇒ 这不是"忠于源码",是**不给自己开 UB 入口**。

★ **位置改了(载入期 → 摇号前),等价性三条判据**:幂等 · 不消耗 rng · 只碰这两列。
⚠️ 代价记明:归一结果不写回 `enc` ⇒ 将来若有别处读 `enc.lv_min`(运维显示等级区间)
读到的是未归一值;本批无第二个读者。

⚠️★ **它们只能靠手造数据覆盖**,而这正是 §9.0.33 ④ 那条教训的**反面**:
那次是"手填数据掩盖了公式值域",这次是**防御性分支只有手造数据能进去**。
⇒ ★ **两种数据都要有,且各自钉住的是不同的东西。**

#### ⑤ ⚠️★★ 反向验证暴露的**不是实现缺陷,是断言防线的缺口**(本批最值钱的一条)

八条注入里有一条**没红**:「把 `baselevel` 而不是已决定的 `out.level` 喂给 `rollSpawnStats`」。
我在注释里写的预期是「`level-1` 变 −1 ⇒ 四维为负 ⇒ 转红」。**算一下就知道那句是错的**:

```
coef = (level − 1) × lvup + init  ⇒  level 0 时 = −4.5 + 10 = 5.5   ★ 仍为正
⇒ 乌力 vital = 30 × 5.5 = 165,而正确值(level 5)是 30 × 28 = 840
```

⇒ 四维只是**小一个数量级**,不是负、不是 0 ⇒ ★★ **`CHECK(vital > 0)` 这种量级断言
对这类错完全没有区分力。** 已补一条**逐值**用例(`vital==840` / `str==336` /
`tough==420` / `dex==700`),补后该注入立刻转红;那句错注释也已改正。

★ 教训与 §9.0.33 ④ 同族但更细一层:那次是**数据的形状**掩盖了错误,
这次是**断言的形状**掩盖了错误 —— 「非 0」与「对」之间差着一个数量级,
而**只有反向验证会去问这个差**。

#### ① 事实:原版那个"笨拙"的宏形式恰好把退化区间定义好了

```c
#define RAND(x,y)  ((x-1)+1 + (int)((double)(y-(x-1))*rand()/(RAND_MAX+1.0)))
```

| 输入 | `y-(x-1)` | 取整 | 返回 | 消耗 `rand()` |
|---|---:|---:|---:|:-:|
| `RAND(5,9)` | 5 | `[0,5)` | 5..9 | ✅ |
| **`RAND(5,5)`** | **1** | **0** | **5** | ✅ |
| **`RAND(0,-1)`** | **0** | **0** | **0** | ✅ |

★★ **两种退化都是有定义的,不是 UB。** ⚠️ 我最初的判断是「原版自己就踩 UB(`RAND(0,-1)`)」,
把式子展开后**当场推翻** —— `y-(x-1)` 在 `y==x-1` 时算出的是 **0**,不是负数。
⇒ ★ 又一次兑现「先把式子展开再下结论」:**"看起来会 UB"和"展开后会 UB"是两件事。**

⚠️ 而 `rand()` 是那个乘法的**操作数**:它有副作用,编译器不得因系数为 0 而消除
⇒ **原版在退化区间上照样消耗一次**。

#### ④ ★★★ 两处「等价写法」,以及我为它们编造的理由 —— 本节最该被读的一段

抽签那一行里有两处细节,我在注释和用例里都当成了**行为判据**:

`r` 遍历 `[0, Σ−1]`,共 **2,580 组**):**两处各自改、同时改,差异均为 0 组。**

| 细节 | 为什么等价 |
|---|---|
| 上界 `found - 1` | `r <= Σ−1 < acc(最后)` ⇒ 最后一个候选**必然**命中 ⇒ 进循环与兜底给它,结果相同 |

⚠️★★ 我的注释原文是「`w != 0` 那半个条件要紧:**权重 0 的槽不该被选中**,少了它会选中它」
—— **那句话是错的**,用例也据此写了一条没有区分力的断言。
