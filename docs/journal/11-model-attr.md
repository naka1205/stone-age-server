### 9.0.24 ★★ L2 实体池地基 —— 阶段 2 领域模型层起步(2026-09-07)

> **关键路径在 1.4 双端跑通后转入阶段 2(L3 战斗批次 A–D + L2 实体族)。战斗批次 A.2/A.4
> 反复撞到同一堵墙:捕获的「生成宠物入队」、打飞的 `pet_hp_delta` 落地、换宠 —— 这些世界写
> 没有落脚点,因为 `shared/model/` 至今只有 `Handle.h`,没有实体池 / 实体族 / 索引。
> 本节先搭 L2 的纯结构地基,把 M2 / M10 与「索引不得线性扫描」在结构上立住。**

#### ① 交付形态:三个纯头 + 一个用例集,零新依赖

| 文件 | 内容 | 守的约束 |
|---|---|---|
| `shared/model/EntityPool.h` | 定长池 `EntityPool<T,N>`:`std::array` 存储、空闲链、generation 句柄回收 | ★ M10 —— `release` 使槽 generation++ 作废旧句柄;`resolve` 校验不匹配返回 `nullptr`(悬空当场变空指针,不脏读复用槽)|
| `shared/model/EntityKind.h` | 五族判别键 `EntityKind`(Player/Pet/Enemy/Npc/WorldObject)+ §2.2/§2.3 两条裁定的边界注释 | ★ M2 —— 和类型不是宽表;kNpc 是一个族不是 47 个类;不复刻字符串→函数指针运行期绑定 |
| `shared/model/EntityIndex.h` | 标识符→句柄哈希索引 `EntityIndex<Key>` + 三个具名别名(Account/CharName/Conn) | ★ 索引不得线性扫描(§8.2)—— 原版四个 `getfdFrom*` 全表扫,`fdnum=1000` 下每条应答扫 1000 次 |
| `tests/ModelPoolTest.cpp` | 11 用例 / 59 断言:池的分配/回收/generation、索引 O(1)、和类型值域 | 结构性硬约束,非公式 |

★ 全部纯头(模板 + inline)⇒ **不改 `shared/CMakeLists.txt` 的 `sa_shared` 源列表**,随消费方编译。
`EntityPool::allocate` 发**干净槽**(复用前 `value = T{}`,原地赋值非堆分配),否则新主人读到前主人脏值。

#### ② 两处分工边界(写进注释,防后来者合并)

- ★ **索引不做 generation 校验**:索引只管「名字→槽」,「槽还是不是那个主人」是 `EntityPool::resolve`
  的活。索引命中的句柄**可能已悬空,这是正常的** —— 两步分工合并会让索引承担它管不了的世代事。
  用例 `索引存的句柄可能悬空` 钉住这条。
- ★ **`EntityKind` 与 `Rules::CombatantKind` 不合并**:一个是领域全集(五族)、一个是战斗输入子集
  (Player/Pet/Enemy 三值)—— 照 `Combatant.h` 卷首「故意不复用同一个类型」的先例各自独立。

#### ③ 复验(本地三工具链 + 反向验证)

### 9.0.26 ★★ L2 实体族接线 —— 批次 M.1,并当场推翻三处记载(2026-09-07)

#### ① ★★ 三处被推翻的记载

⚠️ 行号基准 = `stoneage-plan/tools/unifdef_80/` **展开视图**(§9.0.25 ⑤)。

★ 三者的共同形态:**推迟一件事时,推迟的理由没有回源码/回本仓代码核一遍**。

⚠️ ① 的代价最实在:一个能落地的世界写被搁了三天,而 `ctest` 全程 12/12。

#### ② ★★ 工作单元边界不需要新裁定 —— 源码里已经是「预留 → 提交」

开工前预备请用户裁定的问题是:「捕获成功要写四样东西,其中删道具做不到,那这次算成功还是失败」。
**回源码后这个问题消失了**:`battle_event.c:3512-3517` 里**生成宠物是第一步且是门** ——

```
pindex = PET_createPetFromCharaIndex(…);
if (pindex == -1) { flg = 0; }          ← ★ 失败 ⇒ 后面的删道具/离场/计数一步都不执行
else { PETGETLV · LogPet · CaptureOk · CaptureItemDelAll · GETPETCOUNT++ · BATTLE_Exit · … }
```

三条失败路径(`pet.c:333` 宠物槽满 / `:336` 模板缺失 / `:382` 全局池满)**全排在任何不可回退的写之前**
⇒ 失败时世界状态一个字节都没动,**不需要补偿逻辑**。

⇒ ★★ **`00` §6 那条「gmsv 进程内也需要工作单元边界」在本批第一次有了具体形状,
而它不是我们设计的 —— 回源码核实时它已经在那里。**
★ 这条值得单列,因为 §6 的语气是「原版零回滚 ⇒ 必须新建边界」,
而**捕获这条链原版是对的**;真正零回滚的是 `trade.c:975`(10 步顺序结算)。
⇒ 「原版没有工作单元」是个**过宽的概括**,逐条链要各自核。

#### ③ ★ 「缺落脚点」被精确成两个不同的缺口

`World.cpp` 原先记「生成宠物缺落脚点」。本批发现那是**两件事**:

| 缺口 | 状态 |
|---|---|
| ① 宠物池 / 主人的宠物槽(**写到哪里**) | ✅ **本批已补**:`EntityPool<Pet,2000>` + `Player::pets[5]` |
| ② ★ **敌人侧的 L2 实体(字段的源头)** | ❌ **仍缺**。被捕目标在战场里只是 `Rules::Combatant`(战斗输入子集,存的是已重算的 `attack`/`defense`/`quick`)—— **没有 vital/str/tough/dex 这四个原始属性,也没有名字**。源码从 `enemyindex`(完整 Char 实体)拷 ⇒ 要 `EntityKind::kEnemy` 族 + L4 内容导入,那时 `Combatant` 才是 Enemy 实体的**战斗投影** |

⇒ 本批捕获出的宠物那四项是 **0**,**登记在案的残缺,不是 bug**。
★ 一条用例专门钉住这个事实,免得下一个人以为它填上了。

#### ④ ★★ 顺序陷阱第三例 —— 三套四属顺序两两不同

| 出处 | 顺序 |
|---|---|
| 原版 `CHAR_*AT` 拷贝(`pet.c:348-351`) | **火 水 地 风** |
| `Rules::Element`(`Constants.h:207-213`) | **地 水 火 风** |
| `05` §3.4 相克表表头 | **无 火 水 地 风** |

⇒ 从 `Combatant::elements[]` 拷到 `Pet` 必须**按具名下标取**
(`elements[static_cast<int>(Element::kFire)]`),**绝不按位置拷**。
★ 前两次栽在这一类上分别是「相克表头顺序」与「`BATTLE_ATTR_NONE == 0` 撞 `Element::kEarth == 0`」
(批次 0 归因),两次都是**伤害算错而无一处报错**。

#### ⑤ ★ 容量常量不能配置化 —— 这是定长池的代价,不是遗漏

`kMaxPlayers = 100`(`fdnum`)· `kMaxPets = 2000`(`petnum`),取值来自 `15` §2 的配置表实测
(`csa8.0/setup.cf`);⚠️ `15` C7:真实玩家上限 = `fdnum` − 系统占用 ⇒ 100 是**上界**。

⚠️★ **原版 `fdnum` 是配置项,我们这里是编译期常量** —— 因为 `EntityPool<T, Capacity>`
的 `Capacity` 是模板参数。要让它可配就得改成运行期容量池,而那会丢掉 `std::array` 存储,
正是 `15` §9.1 三根支柱第 ① 条「运行期零分配」的前提。⇒ **有意的取舍,写进代码注释。**

★ 一处很值得记的印证:`15` C4 实测原版角色是**三段式单一数组**
`CHAR_chara[fdnum + petnum + othercharnum]`、按 `CHAR_WHICHTYPE` 选段轮转分配
⇒ **原版本来就是「按族分段的池」**,我们只是把段换成独立强类型池(M2)。
和类型不是我们发明的抽象,是把疤痕化的实现还原成本来的形状。

#### ⑥ ★★ 没有观察面,就没有任何东西能断言「接上了」

欠债 20 的要害原话是「地基绿而运行时不接,`ctest` 一样 12/12 全过」。
⇒ 本批必须同时加**观察面**,否则新代码同样无法被断言:

### 9.0.27 ★★ 批次 M.2 —— 战场态宠物入场地基,纠正命名方向 + 绕开两个源码陷阱(2026-09-07)

> **M.1(§9.0.26)建了宠物的**世界态**(`Player.pets[5]`),但战斗里的宠物一直只有骑乘宠
> (`Combatant::ride_hp`)、没有**独立战斗单位**。本节建**战场态投影**:把一只 `Model::Pet`
> 投影成站在 `slots[主人位次+5]` 的 `Combatant`,并交付入场 / 离场机制 —— 换宠指令(下一批)的地基。**
>

### 9.0.29 ★★ 批次 M.3 —— 属性推导落地,并证伪了 demo 自己的数值(2026-09-08)

#### ① ★★ 真公式不在 `complianceParameter` 里,而在它调的 `CHAR_initcharWorkInt`

`CHAR_complianceParameter`(展开视图 `char/char.c:3525`)是**编排器**:
`CHAR_initcharWorkInt` 建基础值 → `ITEM_equipEffect` / `Other_DefcharWorkInt` 叠装备 →
把 `WORKFIX{STR,TOUGH,DEX}` 拷进 `WORKATTACKPOWER / DEFENCEPOWER / QUICK`。
⇒ 本批移植的是 `:3419-3487` 的**基础段**;装备 / 套装 / 技能加成对**无装备单位输入全 0 即恒等**,
故不含(接口留待装备系统)。★ `FreeComplianceParameter`(`mylua/function.c:830`)是 **Lua 回调**
(自由属性扩展点,D6 脚本层)⇒ 不移植。公式与截断语义的真源在 `11` DR-DT9 §2.9,此处不复述。

#### ② ⚠️★ 又一处文档分叉:**公式里没有 `level`**

不在这一步。⇒ 这是 §9.0.19 那条纪律(动手前回源码核实,不凭文档转述)的**第五次兑现**,

#### ③ ★★ 补了公式,宠物照旧打不动 —— 因为 **0 是推导的不动点**

捕获宠四维 = 0(DR-BT19:战场上的敌人只是 `Rules::Combatant`,**没有四维可拷**)·

#### ① 四步顺序即语义 —— 成长率取「+10 前」、四维取「+10 后」

`ENEMY_createEnemy`(展开视图 `char/enemy.c`)四步:
