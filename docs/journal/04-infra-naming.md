### 9.0.11 ★★ 项目定位澄清与命名前缀裁定(2026-09-04,用户裁定)

> **本节推翻的不是某个实现细节,是三条一直被默认接受、却从未被显式裁定的前提。**
> 它们都来自「本项目起自 `sg_create/template/`」这个历史起点,而那只是**工程骨架的出处**,
> 不构成**架构上的归属**。

| # | 原前提(散在两仓文档) | ★ 裁定 |
|---|---|---|
| **① `sg_studio` 的角色** | §9 卷首:「窗口布局**仍是** `sg_studio` 场景 XML v2 的产物」;客户端 `01` §5.3 / `03` §1.2 据此写「布局用编辑器的场景 XML 产出」 | ❌ **不作为本项目的资产格式来源。** `sg_studio` 面向**单机版**游戏制作,与本项目(服务端权威的联网重制)不契合;当前对它的用途仅限 **UI 布局参考与多平台发布**,后续它会补 MCP 能力,届时再议是否对接 |
| **② `SG::Engine` 的角色** | 客户端 `01` 通篇按「平台映射」组织,读起来像本项目是引擎的衍生品 | ★ **只是客户端渲染层的一个底层框架**,是**可替换的渲染后端**,不是宿主。本项目不是它的衍生品 |
| **③ 两仓的权重** | 两仓文档基本平权(客户端 `01` 有 801 行) | ★ **以服务端为主**,客户端推进节奏显式降级为跟随。⚠️ 这与 D8「核心 29 + 逐步补」和迁移路径 α(双端同步切换)**不冲突** —— α 说的是**切换方式**,不是两端等权 |

#### ★ ① 保留了什么、改了什么(别读成"布局回到代码里")

客户端 `03` §1.2 的裁定是**两句话**,只有第二句被推翻:

| | 原文 | 现在 |
|---|---|---|
| 原则 | **布局是资产,不是代码**(新增窗口 = 加一个布局资产 + 一条 `WindowKind`,不改渲染代码) | ✅ **不变** —— 它挡的是 `menu.cpp` 22,835 行那种"43 个窗口各写一遍" |
| 格式 | = `sg_studio` 的场景 XML v2 | ⚠️ **改为本项目自定**(登记为 **DR-CP13**,`11` §9) |

⇒ 因此这条**不挡 1.4**(已裁定走占位美术),它挡的是 1.4 之后的表现层。

#### ★★ ② 连带解掉一条欠债,而不是新增一条

客户端 `01` §13 欠债 8 一直留着一项未验:
**「`shared/` 与 `SG::Engine` 头**同时**参与编译时的宏 / 符号冲突面 —— 要等 1.4 接表现层」。**

⇒ 按 ② 的裁定,**渲染层单向依赖引擎,`shared/` 根本不该与引擎头相遇** ——
那不是"迟早要面对的风险",而是**本来就该成立的隔离**。
⚠️ 但它从"等 1.4 回答"变成**"要有东西守住"**:与其等冲突发生,不如让它不可能发生
⇒ 该项改为**客户端侧的一条依赖方向检查**(与 `tools/check_shared_purity.py` 同族,
后者守 `shared/` 不依赖服务端设施,新的这条守 `shared/` 不被引擎上下文污染)。

#### ★★ 命名前缀:`sg_` → `sa_`(用户拍板 2026-09-04)

② 的直接后果:**本项目自有的标识符不应再用 `sg` 前缀** —— 那是平台的前缀,
沿用它等于在每一个目标名、每一个 option 上重复声明一个已被否定的归属关系。

**新前缀 `sa_` / `SA_` / `sa::`**(与原版简称一致:`csa8.0` / `SA8.0`),
★ 选它还有一个可执行的好处:**与外部 `SG::` 一眼可分** —— 而"分得清"正是 ② 要表达的东西。

| 类 | 例 | 处置 |
|---|---|---|
| **外部资产** | `SG::Engine` · `SG::Director` · `SG::Scene` · `sg_engine` · `sg_gameplay` · `sg_create` · `sg_studio` | ❌ **不改** —— 那是别人的 API 与目标名 |
| **本项目自有** | 目标 `sg_shared` / `sg_idl` / `sg_net` / `sg_platform` / `sg_world` · 函数 `sg_apply_warnings` / `sg_enable_assertions` · option `SG_WERROR` / `SG_SHARED_*` / `SG_CLIENT_*` · 头 guard · 命名空间 `sg::` | ✅ **全改** |
| **IDL 侧**(裁定含在内) | codegen 包 `sgidl` · 运行时头 `sg_idl_runtime.h` · 扩展 `sg_options.proto` · ★ 生成物后缀 **`.sg.h` → `.sa.h`** | ✅ **全改** ⇒ 8 份生成物全量重生成并重新入库(DR-TS2) |

⚠️★ **三处会让改名"改一半就红"的耦合,必须同批完成**:

| # | 耦合 | 漏改的后果 |
|---|---|---|
| ① | 客户端 `SgShared.cmake` 的 `SG_SHARED_GIT_TAG` / `SG_SHARED_SOURCE_DIR` / `SG_SHARED_GOLDEN_TEST` ↔ 服务端 `shared/CMakeLists.txt` | **跨仓契约**,两仓必须同批 + 重新打 tag |
| ② | 两仓 `tools/ci_verify.py` 的 `EXPECTED_TESTS` 写的是**目标名字面量** | §9.0.9 那道「测试注册清单断言」直接失败 —— ★ 但这**正是它该有的行为**,不要为改名放宽它 |
| ③ | `tools/check_shared_purity.py` 与 `win_validate.ps1` 里按名字匹配的检查 | 静默失效(**比失败更坏**,`00` §10.4) |

⇒ **执行时机:排在批次 A 开工之前。** 两仓此刻都干净、CI 刚全绿、`shared-v0.1.0` 刚打出,
是成本最低的时刻;等批次 A 的 720 处移植铺开,冲突面会大得多。
⚠️ 改名后须**重新打 tag 并前推客户端锁定 ref**(`shared-v0.2.0`),
且按 §9.0.9 的双 push URL **两仓 × 两远端一起推**。

### 9.0.23 ★★ 命名改造 P0–P6 —— 全盘对齐引擎 GameStudio(2026-09-07)

> **DR-TS7(2026-09-04)只裁定了前缀 `sg_`→`sa_`。2026-09-07 用户进一步裁定「全盘对齐
> GameStudio 引擎风格」,把服务端与 `shared/` 原来的 Google 风改造成引擎款,并把命名空间
> 从小写 `sa::` 提到大写 `SA::` 镜像 `SG::`。两仓对称执行,一次推清。**

#### ① 六阶段 + 聚合头改名,范围是"本项目自有标识符全改、外部资产不动"

| 阶段 | 内容 | 规模 |
|---|---|---|
| P0 | `.clang-format`(Tab/Allman)+ `.clang-tidy`(`_camelCase` 成员 / camelBack 方法)落盘 | 基建 |
| P1 | 命名空间 `sa::` → `SA::` 全段大驼峰 | 服务端 578 处 |
| P2 | 去接口 `I` 前缀(`IRandom`/`IClock`/`ITransport`/`IClientSessionHost` ⇒ 抽象类不加 I) | — |
| P3 | 成员变量尾下划线 `x_` → 前导下划线 `_x` | — |
| P4 | 方法名 PascalCase → camelBack | — |
| P5 | 文件名 snake_case → PascalCase + guard 收口(`__SA_<File>_H__`) | — |
| P6 | clang-format 全仓格式化(引擎款)+ 修订 DR-TS7 记为「`SA::` 大写」 | — |
| 附 | 服务端聚合头 `api.h` → `Api.h`(`e5497eb`,覆盖 P5 当初对聚合头的例外) | net/platform/world |

⚠️ **边界与 DR-TS7 一致**:`SG::` 族、`sg_*` 目标名、`sg_studio` 等外部资产**一律不改**;
IDL 生成物(`*.sa.h`、`sa_idl_runtime.h`)与 codegen 支撑文件的 snake_case 文件名 + 尾下划线
成员**不在改造范围**(生成链路产物,由 codegen 统一形态)。⇒ 事后核对残留时,这两类是
**预期例外**而非遗漏。

#### ② CI 兜底抓到三类「只在非 macOS 暴露」的问题 —— macOS 双盲区

改造在本地(Apple clang)全绿后推 CI,三平台矩阵抓到三条 macOS 上永远看不到的:

| # | 问题 | 为什么只在非 macOS 暴露 |
|---|---|---|
| ① | `SaShared.cmake` 发布态 pin 停在旧 tag `shared-v0.8.0`(指向重命名前的 `48cc474`) | macOS **大小写不敏感** ⇒ fetch 到旧名 shared 仍能解析;Linux/MSVC 解析失败。**改锁 server master SHA `e5497eb` 修复** —— 命名改造阶段按裁定不新增 `shared-v*` tag。⚠️★ **本行的归因不完整,2026-09-07 审查修正见 §9.0.25 ②**:该 tag **从未推到任一远端** ⇒ 更根本的一层是「pin 指向了一个远端不存在的 ref」,而不只是大小写 |
| ② | `ci_verify.py` / `win_validate.ps1` 硬编码 `constants.h`(P5 已改 `Constants.h`) | 同大小写不敏感 ⇒ Linux/MSVC `FileNotFoundError`。已修为 PascalCase(`3dee1dc`) |
| ③ | `NetTcpTest.cpp` 的 `#if defined(_WIN32)` 分支残留 `fd_`/`RawClose`(P3/P4 的 sed 对平台分支有盲区) | Apple clang 不编译 Windows 分支 ⇒ MSVC C2065/C3861。已修(`719ed9c`) |

★ 三条同族:**本地只有一套工具链(Apple clang)+ macOS 大小写不敏感** 构成双盲区 ——
与 §9.0.16/§9.0.17 那族「只有真跑/换平台才暴露」同源,只是这次触发面是**大小写与平台分支**。
⇒ 改造收口后两仓 × 两远端一起推,GitHub Actions 三平台(Apple clang / GCC / MSVC)最新 run 全绿:
server 至 `719ed9c` · client 至 `8c5cb16`。
