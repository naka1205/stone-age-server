# deviations — 和原版哪里不一样

> **四份文件答四个不同的问题**,别混:

| 文件 | 答的问题 | 一句话 |
|---|---|---|
| [`01-intentional-changes.md`](01-intentional-changes.md) | 哪些**实现方式**有意改了? | 行为保留,做法换了 |
| [`02-faithful-quirks.md`](02-faithful-quirks.md) | 哪些**明知有问题仍照抄**? | 改掉它才是 bug |
| [`03-not-ported.md`](03-not-ported.md) | 哪些**有意不做**? | 不属 8.0 净核,或 D8 排除 |
| [`04-doc-vs-source.md`](04-doc-vs-source.md) | 哪些**我方文档写错了**? | 取证教训,非交付物属性 |

⚠️ **前三份是「我方实现 vs 原版」,第四份是「我方文档 vs 原版源码」** —— 性质不同,各自独立。

## ⚠️★★ 三条使用规则

**① 本目录全部是派生索引,不是真源。**
每条只给一句话 + 指回 [`../journal/`](../journal/) 或 [`../11-decision-register.md`](../11-decision-register.md)。
**若本目录与那边冲突,以那边为准。**
⇒ 理由:同一事实两处存放必然漂移。本目录的价值在**汇总视图**,不在内容本身。

**② 判断一条改动是否合法,回 journal 读判据,别只看这里的摘要。**
每条划外 / 照抄 / 改变在 journal 原文里都写明了当时的判据。

**③ ★★★ 最该记的一条纪律(纪律 ⓪)**:

> **别给照抄的源码编造「它很要紧」的理由。**
> 我倾向于把「不理解为什么这么写」补完成「它一定有理由」,而那个理由不经检验。

⇒ 照抄没错,但注释写「**实测等价 / 冗余,照抄但不声称要紧**」;
⚠️ **别给冗余分支补断言** —— 冗余的分支没有能区分它的输入。

## 一条贯穿全目录的判据

> **★ 「硬编码图号是实现方式,不是玩法」**(DR-BT11 立)

⇒ 玩法效果必须逐位保留,实现方式可以换。
⇒ 推论:**凡改动能被返回值或 rng 序列观察到的,一律不算「有意改变」,属 bug 或必须回退。**

⚠️★★★ 其中 **rng 序列**这一面最隐蔽 —— 值对了但之后所有随机数整体平移,
**返回值断言永远抓不到**(见 [`02-faithful-quirks.md`](02-faithful-quirks.md) §3)。
这类改动唯一能拿到的正确性证据是**三处逐位一致**(本地 server · 客户端联调态 · CI 发布态)。
