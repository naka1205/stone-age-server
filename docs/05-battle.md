## 1. ★★ L3 纯函数边界

### 1.1 为什么它是"需中等改造"而不是"直接可行"

`07` §11.3 的五条实测判据:

| # | 判据 | 实测 |
|---|---|---|
| ① | 规则叶子函数是否已无副作用 | ★ **20 / 23** 个 ≤150 行的叶子函数**零写零 I/O** |
| ② | 副作用是否集中 | ★ 122 次写里 **105 次(86%)** 在 `BATTLE_Battling` + `BATTLE_DamageSub` 两个函数 |
| ③ | 真 I/O 是否集中 | ★★ **44 处全部在 `BATTLE_Battling` 一个函数内**,其余 25 个函数为零 |
| ④ | 随机源是否可注入 | ★ 166 处只经 **2 个入口**(`RAND` / `rand`) |
| ⑤ | 全局耦合面 | 16 个:10 个 `g*` 是本回合临时参数、5 个是串缓冲,**真正的世界状态只有 `BattleArray` 一个** |

★ **四条主公式(伤害 / 回避 / 暴击 / 相克)已经天然是纯的** ——
只读 `CHAR_getWorkInt` + 调 `RAND()`,零写零 I/O。

**阻力在包装层**:`BATTLE_Battling`(1,983 行)把"回合调度 + 指令分发 + 战斗串拼装 +
发包 + 经验掉落结算"揉在一起,且 **10 个 `g*` 文件级全局充当跨函数隐式传参**
(`gWeponType` / `gDamageDiv` / `gBattleStausChange` / `gDuckPer` …)
⇒ **调用顺序本身就是语义**。

### 1.2 四步改造(阶段 0.1)

| 步 | 改什么 | 触及点数 | 触碰公式? |
|---|---|---:|:-:|

## 2. 状态机与时序

### 2.1 战场模式

`07` §2.1 的九个态,新实现只需其中 **4 个**:

| 值 | 模式 | 处置 |
|---:|---|---|
| 1 | `INIT` | ✅ 先手判定 → 回合准备 → 开场 |
| 2 | `BATTLE` | ✅ **主体**:等指令 → AI → 结算 |
| 3 | `FINISH` | ✅ 结算、PK 传送、交易兑现 |
| 4 | `STOP` | ❌ 源码注释标「未使用」 |
| 5 | `WATCHBC` | ✅ 观战初始化 |
| 6–9 | `WATCHPRE/WAIT/MOVIE/AFTER` | ❌ ★ **源码注释均标「没作用」**,视图里都是几行的桩 |

★ **观战的 4 个态是空壳**:真正的观战推进靠主循环遍历观战链下发快照。
**新实现不必照搬这 4 个态。**

### 2.2 一个回合

```
turn(battle):
  1. 两侧「指令齐备」判定        ← 敌方直接视为齐备
  2. 观战链推进
  3. 超时检查                    ← BATTLE_TIME_LIMIT = 3600 s
  4. turn++
  5. AI 决策(两侧)
  6. ★ resolve_turn(...)         ← L3 纯函数,本模块的核心
  7. 清「先制」标志
  8. 胜负判定
  9. 下一回合准备(见 §2.3)
```

### 2.3 ★ 回合准备的四件事 —— 这才是"回合"的真正边界

`07` §2.2 的 `BATTLE_PreCommandSeq`:

1. 下发角色状态快照;
2. 备份入场表;
3. 置「等指令」态并下发就绪位图;
4. ★ **逐角色重算三围** —— `CHAR_complianceParameter` **先把三围重置为基础值**,
   再由 `BATTLE_TurnParam` 往上加。

★ **属性增减的衰减器**:

```
modparam *= 0.8                             每回合衰减 20%
最终值 += modparam * 0.01                   ★ 只按 1% 折算
```

⇒ **战斗中的临时增益不会跨回合累积。** 这是玩法级事实,不是实现细节。

### 2.4 入场上限

| 常量 | 8.0 值 | 说明 |
|---|---:|---|
| `BATTLE_ENTRY_MAX` | **10** | ★ `_MULTIPLAYER_` 在 8.0 为关,`SSRC80` 连 `#ifdef` 都没有(硬编码 10/5/10) |
| `BATTLE_PLAYER_MAX` | 5 | |
| `SIDE_OFFSET` | 10 | 双方各占一段索引 |
| 就绪位图宽度 | **20** | = 2 side × 10 entry;客户端基线亦为关 ⇒ **双端一致** |

### 2.5 行动顺序

```
排序键 = dex + sequence
  dex      = BATTLE_DexCalc(...) —— 基数 WORKQUICK + 20,按指令种类 9 档修正
  sequence = 装备「先攻」属性
```

**分档修正**(`07` §2.3,节选):

| 指令种类 | dex |
|---|---|
| 变身小狐狸 / 恐惧 | `× 0.8` |
| 火/冰/雷附体 | `− RAND(0.3w, 0.5w)` |
| 疾速攻击 | `+ 30%` |
| 暗月狂狼 | `+ 20%` |
| 使用道具 | `− RAND(0, 0.1w) + 15%` ⇒ 净 +5%~+15% |
| **默认(普攻/防御)** | `− RAND(0, 0.1w)` |

⚠️ **两条必须注意**:

- `if (dex <= 1) dex = 1;` **已被注释掉** ⇒ **dex 可为 0 甚至负**;
- ★★ **`EsCmp` 是布尔比较器,不是三态** —— 小于与等于都返回 0,不满足严格弱序
  ⇒ **同速角色的相对顺序在标准库层面是未定义的**。
  **新实现必须显式定义同速裁决规则**(建议按入场位次),否则"照抄公式"也复现不了顺序。
  这是 `00` §10.2 六项永久不可判定之一。

### 2.6 ★★ 节拍层:8.0 没有回合门

`07` §2.1 / `15` §5.2 三证一致:`_BATTLE_TIME` 在 8.0 为**关**
(getter 不在 B80 + 配置键不在 B80 配置表 + `csa8.0/setup.cf` 未赋值)。

⇒ ★ **每 tick 推进所有活跃战斗一步,战斗速度 = tick 频率。**
原版的实际手感取决于当年的硬件与网络。

**新实现必须显式建模节拍**,且它是**玩法参数不是性能参数**:

| 参数 | 含义 |
|---|---|
| `battle_turn_interval` | 战斗回合间隔 —— ★ **热可调**,与客户端动画时长联动 |
| `tick_hz` | 模拟频率,固定,不影响玩法 |

⚠️ **这一层没有可参照的正确答案,只能靠调**(`00` §0 第 ④ 层)。

⚠️ **一个极易在重构中丢掉的细节**:`BATTLE_Loop` 开头有一次**裸 `rand()` 空推**
(不消费结果,只推进序列)⇒ **确定性随机源的重放必须复现这次空推**,否则序列全错。

## 3. 数值公式

> 全节的常量已跨版本核对 **8/8 一致**:`DAMAGE_RATE 2.0` / `DEFENSE_RATE 0.5` /
> `CRITICAL_RATE 1.0` / `KAWASHI_MAX_RATE 75` / `AJ_UP 1.5` / `AJ_SAME 1.0` /
> `AJ_DOWN 0.6` / `ATTR_MAX 100`。

### 3.1 伤害主公式

**第 1 步 —— 取攻防**

```
attack  = 攻击力(攻方)                        无骑宠
        = 0.8·人 + 0.8·宠                       有骑宠·近战
        = 1.0·人 + 0.4·宠                       有骑宠·投掷

defense = 0.70 × 防御力(守方)                  ★ 系数由 _BATTLE_NEWPOWER 决定(8.0 开)
```

⚠️ **关闭时是完全不同的公式**:`0.45·DEF + 0.2·QUICK + 0.1·FIXVITAL` —— **敏捷与体力也参与防御**。
★ 这是"宏切换改变公式形状"的最典型一处,**必须标注门控**。

**第 2 步 —— 防御修正**(依次叠加)

| 条件 | 修正 |
|---|---|
| 铁壁防御 | `defense += defense × (OTHERSTATUSNUMS + rand()%20)/100` |
| 守方是敌人 | `defense += (defense × (rand()%10) + 2)/100` |
| 攻方是敌人 | `attack += (attack × (rand()%10) + 2)/100` |
| 守方石化 | `defense × 2.0` |
| 攻方用「舍己」 | `defense = WORKFIXTOUGH`(**忽略装备**) |
| 攻方有「无视防御 N%」 | `defense × (1 − N/100)` |

⚠️ **括号位置**:是 `(defense × rand + 2) / 100`,**不是** `defense × (rand + 2)/100`。

> ⚠️★ **2026-08-31 更正(移植期对源码复核)**:本节原写「`rand()%10 == 0` 时该项 =
> `2/100` = 0(**整数除法**)」—— **不成立**。`battle_event.c:1164` 是
> `float attack, defense;` ⇒ 该式是**浮点除法**,`rand()%10 == 0` 时该项 = **0.02**。
> 括号位置的结论不变,变的是"整数除法"这个归因。

**第 3 步 —— ★ 三分段主公式**

```
defense > attack                    → damage = RAND(0, 1)              只能造成 0 或 1
defense ≤ attack < defense·8/7      → damage = RAND(0, attack/16)
attack ≥ defense·8/7                → K0 = RAND(0, attack/8) − attack/16
                                      damage = (attack − defense)·2.0 + K0
```

★ **攻防比 8/7 是质变阈值。** 低于它伤害几乎为 0,超过它则线性放大 2 倍。
`K0` 是**零均值抖动**,幅度 ±`attack/16`。

⚠️ 三个分支用 `else if` 串联。**源码顺序是**:第二分支 → 第一分支 → 第三分支
(`battle_event.c:1225-1235`),上表按语义重排过 —— 三条件互斥,结果相同。

> ### ⚠️★★ 一处已被实测推翻的结论(2026-08-31 更正)
>
> 本节原写:「第二分支上界用**浮点** `defense*8.0/7.0`、第三分支下界用**整数除法**
> `defense*8/7` ⇒ 边界处存在**两分支都不命中的窄缝**,此时 `damage` 保持初值 **0**。」
>
> **两个论断都不成立**:
>
> | # | 原文 | 实测 |
> |---|---|---|
> | ① | 第三分支下界是**整数除法** | ❌ `attack`/`defense` 是 **float**(`:1164`)⇒ `defense*8/7` 是浮点运算 |
> | ② | 存在**窄缝**,damage 保持 0 | ❌ **0 组窄缝**。float 口径穷举 2,862 万组 → 0;即便按原文的整数除法口径扫 20 万 defense → 0 组窄缝、**171,429 组重叠** |
>
> ★ **方向恰好相反**:整数除法只会让下界**变小** ⇒ 产生的是**重叠**而非缝,
> 而 `else if` 让**第二分支**接管重叠区间。
>
> ⇒ **边界值走 `RAND(0, attack/16)`,不是 0。**
> ⚠️ 照原文实现"窄缝返回 0"会**引入原版没有的行为**。
>
> 回归断言:`tests/rules_battle_test.cpp` 的
> 「三分段:无窄缝,阈值边界走第二分支而非返回 0」。

**第 4–6 步**:四属性相克(§3.4)→ 四属结界减伤 → 附加伤害/减免。

⚠️ 四属结界**按地水火风顺序 `else if` 串联** ⇒ **只有第一个命中的结界生效,不叠加**。

**第 7 步 —— ★ 全局伤害系数**

```
damage = max(damage, 0) × getDamageCalc() / 100
```

★★ **`getDamageCalc()` 的默认值是 70,不是 100**:

| 配置 | 值 |
|---|---|
| `csa8.0/setup.cf` | **未赋值 ⇒ 走 getter 兜底 = 70** |
| `StoneAge/gmsv/setup.cf` | 70 |
| `stoneage85/setup.cf` | 85 |

⇒ **8.0 投产下,全部物理伤害统一乘 0.70。**

```
             = 0.02   否则

per = √((Big − Small) / gKawashiPara) · wari + Df_Luck + gBattleDuckModyfy
per += RAND(20,30)   若攻方酒醉          ← ★ 酒醉真正生效处
per += 20            若攻方持弓
per ×= 100;  per = clamp(per, 1, 7500)   ★ 回避率硬上限 75%

若攻方是玩家:per −= RAND(0.8·命中率装备, 1.2·命中率装备)
职业「回避」技:per × (100 + lv)/100
若攻方用「混乱攻击」:per += per·0.4       ★ 命中降低 40%

命中判定:RAND(1, 10000) ≤ per → 闪避成功
```

⚠️ **闪避成功时嵌了技能升级副作用**(`PROFESSION_SKILL_LVEVEL_UP`)——
这是 §1.2 第 ② 步要剥离的典型:**判定函数不得写世界状态**。

### 3.3 暴击

⚠️ **两个分支调用同一个函数**(曾区分玩家/非玩家,现已退化)⇒ **新实现只需一条路径**。

```
divpara = gCriticalPara = 0.09;  root = 1
类型修正:宠→敌 Df_Dex×0.8
         ★ 敌→宠 或 非玩→玩:divpara = 10.0, root = 0   ⇒ 分母暴增 111 倍,暴击率极低
         玩→非玩 Df_Dex×0.6

per = (root ? √Work : Work) + 装备暴击·0.5      Work = (Big−Small)/divpara
per ×= wari;  per += At_Luck;  per ×= 100;  per = clamp(per, 1, 10000)
★ 守方图号 == 101813 / 101814(雷尔) ⇒ per = 0   ← 硬编码免疫

暴击伤害 = DamageCalc + 守方防御 × LV攻/LV守 × 0.5
```

⚠️ 两处附带副作用:暗月狂狼时 `perCri × 1.3` 且**当场把攻方攻击/敏捷各 +20%**;
★ **持弓不吃暴击伤害加成**(只记标志位)。

### 3.4 四属性相克

**5×5 全展开矩阵**:

| 攻\守 | 无 | 火 | 水 | 地 | 风 |
|---|---|---|---|---|---|
| **火** | 1.5 | 1.0 | 0.6 | 1.0 | 1.5 |
| **水** | 1.5 | 1.5 | 1.0 | 0.6 | 1.0 |
| **地** | 1.5 | 1.0 | 1.5 | 1.0 | 0.6 |
| **风** | 1.5 | 0.6 | 1.0 | 1.5 | 1.0 |
| **无** | 1.0 | 0.6 | 0.6 | 0.6 | 0.6 |

```
取值:T_pow[0..3] = 地水火风基础值,叠加装备属性后单属上限 100
      T_pow[4]   = max(0, 100 − Σ其余)          ← 无属性余量
结果 = damage × Σ(攻方各属 × 守方各属 × 系数) / 10000
```

★ 因 `Σatk = Σdef = 100`,全无属性时系数为 1.0 ⇒ **量纲自洽**。

**场地属性**:`power = 0.5`(默认)或 `0.5 + 该属值·att_pow·0.0001·0.5`;
最终 `damage × (At_FieldPow / Df_FieldPow)`。★ 分母最小 0.5,不会除零。

### 3.5 防御与反击

**防御减伤是六档随机**,不是固定系数:

| `RAND(1,100)` | 系数 | 概率 |
|---|---:|---:|
| ≤ 25 | **0.00** | 25% |
| 26–50 | 0.10 | 25% |
| 51–70 | 0.20 | 20% |
| 71–85 | 0.30 | 15% |
| 86–95 | 0.40 | 10% |
| 96–100 | 0.50 | 5% |

⇒ **期望系数 ≈ 0.155,且 25% 概率完全免伤。**
★ 触发条件:守方指令 = 防御 **且 混乱值 ≤ 0**。

**反击**:

```
per = √((Big−Small)/0.08) · wari · CounterTbl[攻武器类][守武器类] · 0.1 + At_Luck + WORKCOUNTER
反击伤害 = damage × 0.75(下限 1)
```

`CounterTbl` 武器相性(7 行 × 8 列):

| 攻\守 | 无 | 爪 | 斧 | 棍 | 矛 | 弓 | 投 | 其它 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 无 | 10 | 9 | 8 | 8 | 5 | 0 | 0 | 0 |
| 爪 | 10 | 9 | 7 | 7 | 6 | 0 | 0 | 0 |
| 斧 | 9 | 8 | 10 | 10 | 7 | 0 | 0 | 0 |
| 棍 | 8 | 8 | 10 | 10 | 7 | 0 | 0 | 0 |
| 矛 | 6 | 6 | 8 | 8 | 9 | 0 | 0 | 0 |
| 弓 | 0 | 0 | 0 | 0 | 0 | 0 | 0 | 0 |
| 投 | 0 | 0 | 0 | 0 | 0 | 0 | 0 | 0 |

★ **投掷武器双向禁反击**:攻守任一方是投掷即 `return FALSE`,比查表更早。表里两行全 0 是第二道保险。

⚠️ **表缺第 8 行**(`BATTLE_C_OTHER`):索引式需要 64 元素,表只有 56。
现在不触发是因为 `BATTLE_ItemType2ItemMap()` 永不返回 `OTHER`;
★ **重构时若扩充武器类型会立刻越界。**

### 3.6 骑宠伤害分摊

```
playerdamage = damage · petDef / (myDef + petDef) + 1
petdamage    = damage − playerdamage + 1
```

⚠️ **两处必须显式决策的反直觉**:

1. **两处 `+1` 使总伤害比原值多 2**;
2. ★ **分摊比例反直觉**:宠物防御越高,**人吃的伤害越多**(`petDef` 在分子)。

两版血统一致 ⇒ **不是笔误就是设计,须决策后再改**(§9)。

★ **骑宠死亡的连带**:`pethp ≤ 0` ⇒ 解除骑乘 + 换回原图 + 置落马标记。

### 3.7 六种反应类型

| 反应 | 效果 | 计数器 |
|---|---|---|
| 吸收 | `hp += damage`(回血) | −1 |
| 反射 | 伤害转给攻方 | −1 |
| 消失 | 伤害归零 | −1 |
| 陷阱 | 伤害改为固定值并转给攻方 | 清零 |
| 针刺 | **双方都受伤**:守方全额、攻方半额;damage 强制偶数 | 清零 |
| 无 | 正常扣血 | — |

★ **投掷武器不触发反射/陷阱/针刺**(三处各自判定)。

### 3.8 「打飞」判定

```
damage ≥ maxhp·1.2 + 20                   → 一击打飞
否则溢出伤害累积 ≥ maxhp·1.2 + 20         → 累积打飞
★ 守方图号 101813/101814(雷尔)          → 免疫
```

### 3.9 攻击次数

```
有武器:RAND(武器 ATTACKNUM_MIN, MAX),≤0 则 1
空手(itemindex 无效):
    lv < 10 或非玩家 → 1
    否则 luckwork = LUCK×5(上限 25);randwork = RAND(1,1000)
         ≤ 10+luck → RAND(5,10)   ★ 空手连击可达 10 段
         ≤ 30+luck → 3
         ≤ 70+luck → 2
         否则       → 1
```

⚠️ ★ **`gDamageDiv` 的两条路径不同**:

- 有武器且是拳套:`gDamageDiv = attack_max` ⇒ **总伤害不变、分摊到多段**;
- **空手**:`gDamageDiv` 保持 1.0 ⇒ **多段各自全额** ⇒ **空手 10 连击是纯收益**。

两版一致 ⇒ 见 §9 的决策清单。

## 4. 状态异常

### 4.1 ★★ 全局互斥 —— 本模块最重要的单条结构事实

```c
for (i = 1; i < BATTLE_ST_END; i++)              /* ★ 扫全部 43 种 */
    if (CHAR_getWorkInt(defindex, StatusTbl[i]) > 0) return FALSE;
```

⇒ **目标身上只要有任意一种状态异常,新状态一律施加失败。**
**不是同类互斥,是全类互斥。**

★ **架构含义**:状态系统**不是**「多个独立计时器」,而是「**单槽状态机 + 43 个候选**」。
⚠️ **新实现若按"每种状态一个独立字段、可并存"设计,行为会与原版完全不同**
—— 玩家会同时中毒+麻痹+沉默,而原版永远只有一种。

> ⚠️ **例外存在,是双轨制不是 bug**:职业技能专用的施加路径**没有这个互斥循环**,
> 只检查目标存活与三属抗性互斥。
> ⇒ **职业技能可以给已有状态的目标叠加新状态,普通攻击与宠物技能不行。**
> **新实现必须保留两条路径的差异。**

### 4.2 ★★ 虚弱 / 魔障使全部计时器冻结

```c
CHAR_setWorkInt(idx, StatusTbl[i], --cnt);                     /* 正常递减 */
if (WORKWEAKEN  > 0) CHAR_setWorkInt(idx, StatusTbl[i], cnt+1);/* ★ 加回去 */
if (WORKBARRIER > 0) CHAR_setWorkInt(idx, StatusTbl[i], cnt+1);/* ★ 加回去 */
```

⇒ 中虚弱或魔障期间,身上所有状态的回合数**都不减少**。
★ 又因 §4.1 的全局互斥,"身上所有状态"实际只有虚弱/魔障自己 ⇒
★★ **虚弱与魔障一旦施加就永不自然解除**,只能靠:离场/进场清除、马杀鸡技能、精灵解除。

⚠️ **这是玩法级强约束**:虚弱/魔障在原版里等于「持续到战斗结束」。

### 4.3 命中率

**麻痹走独立分支**:`per = 20 − 抗性 − 装备抗性`,`max(per, 0)`
⇒ **固定基数 20**,不看等级差、不看幸运、不看体力。

**其余 42 种走通用分支**:

```
fVitalP = VITAL / (VITAL + STR + TOUGH + DEX)
若 status == 毒煞:fVitalP = (1 − fVitalP) · 0.9        ★ 反过来
fVitalP = fVitalP / 0.25 × 10.0                        ⚠️ 四个类型分支值完全相同 ⇒ 新实现只需一条

level = (LV攻 − LV守) × Bai,夹到 ±Range               ← PvP 时 level = 0
per = PerOffset + level + 攻方幸运 − 守方抗性 − fVitalP − 通用抗性 − 装备抗性
per = min(per, 80)                                     ★ 命中率硬上限 80%
命中:RAND(1,100) < per
```

**三组调用参数**:

| 场景 | `PerOffset` | `Range` | `Bai` |
|---|---|---:|---:|
| 普攻附带状态 | `suitpoison`(默认 **30**) | 40 | 2.0 |
| 精灵 / 魔法 | 技能表 `Success` | 30 | 1.0 |
| 魔障 / 沉默技 | `Success` | 30 | 1.0 |

### 4.4 ★★ 酒醉:不能照抄代码,必须照抄意图

```
施加时:CHAR_WORKDRUNK /= 2     ← ★ 改的是「回合数」计数器
解除时:CHAR_WORKQUICK *= 2     ← ★ 敏捷 ×2
```

★★ **不对称:解除时把敏捷乘 2,但施加时从未除以 2。**
全库实测:**没有任何一处把 `CHAR_WORKQUICK` 减半**。

⇒ **净效果:中酒醉再解除,敏捷翻倍。** 但活不过一个回合 ——
回合准备会把敏捷重置回基础值(§2.3)⇒ **可观测窗口 = 解除当回合的剩余结算**。

★★ **酒醉真正生效的地方是回避判定**:「攻方酒醉时守方回避率 +RAND(20,30)」(§3.2)。
⚠️ **从 `BATTLE_DexCalc` 看不出酒醉降敏。**

## 6. 逃跑 / 捕获 / 救援 / 观战

### 6.1 逃跑

```
PvP → ★ 直接成功(PK 中必定逃脱)
luck = 敌人:RARE 0→1 / 1→3 / 其它→5;玩家:clamp(幸运, 1, 5)
escape_cnt = 本角色累计逃跑次数 + 1          ★ 失败也累积

luck ≥ 5 → Esc = 95 · escape_cnt
luck = 4 → Esc = 60 · escape_cnt − 2·ΔLv
luck = 3 → 50 · cnt − 2ΔLv;  = 2 → 40 · cnt − 2ΔLv;  = 1 → 30 · cnt − 2ΔLv
敌方无存活 → Esc = 100;  Esc = max(Esc, 1)
成功:RAND(1,100) < Esc
```

★ **`escape_cnt` 是线性放大器**:第 2 次尝试概率翻倍,第 3 次三倍 ⇒ **多试必逃**。
⚠️ 且是**先 ++ 再判定** ⇒ 首次尝试即 `escape_cnt = 1`。

### 6.2 捕获

**四道前置**:目标是敌人 / 目标带可捕获标记 / ★ 除非有特殊技否则 `myLv + 5 < 目标Lv` 直接失败 /
条件道具检查。

```
Df_HpPer = 10 − (HP · HP) / MaxHP          ★ 二次式:HP 越低值越大
Df_Level = myLv/2 − targetLv/2             (整数除法)
Df_Dex   = myDex/15 − targetDex/15
WorkGet  = (Df_HpPer + Df_Level + Df_Dex + (捕获难度 + 攻方幸运)) × 攻方魅力 / 50
WorkGet += 捕获率提升;  目标睡眠 +15;  min(WorkGet, 99)     ★ 上限 99%
成功:RAND(1,100) < WorkGet
```

★ **魅力是乘性主因子**(`/50` ⇒ 魅力 50 时系数为 1)。
★ **`Df_HpPer` 是二次的** ⇒ 满血几乎抓不到。

**条件捕获道具表**(硬编码 11 条,`07` §6.2):特定敌人需要特定道具,
其中 **1 个敌人需同时持有 3 件**。

★ **捕获成功后删除全部条件道具** —— 源码注释明确「抓到一只宠只删除一个道具
(**最後还是决定全删**)」⇒ **这是已被开发者显式决策过的行为,不是 bug。**

### 6.3 救援与观战

| | 救援 | 观战 |
|---|---|---|
| 已在战斗中 | ❌ 拒绝(★ 防作弊补丁,`#if 1` 恒真) | — |
| 已组队 | ❌ 拒绝 | — |

## 8. 随机源

### 8.1 `RAND` 的真实语义

```c
#define RAND(x,y)  ((x-1)+1 + (int)((double)(y-(x-1)) * rand() / (RAND_MAX+1.0)))
```

化简 = `x + (int)((y − x + 1) · rand()/(RAND_MAX+1.0))` ⇒ **闭区间 `[x, y]`**。

⚠️ **三个坑**:

1. **参数可以是浮点表达式**(如 `RAND(0, attack/16)`)⇒ 中间是 double 运算,最后 `(int)` 截断。
   **重放时必须保留浮点中间值**,否则边界值会差 1;
2. `(x-1)+1` 在 x 为浮点时不等于 x(先减后加有精度损失),但因最终取整实测无差异 ——
   **照抄即可,不要"简化"**;
3. ★ **被注释掉的旧版语义不同**(是 `[x, x+y]`)⇒ **切勿参考注释里那一行**。

### 8.2 166 个随机点的分布

| 文件 | `RAND` | 裸 `rand()` | 合计 |
|---|---:|---:|---:|
| `battle_event.c` | 52 | 11 | **63** |
| `battle.c` | 51 | 8 | **59** |
| `battle_magic.c` | 19 | 6 | 25 |
| `battle_ai.c` | 11 | 0 | 11 |
| `pet_skill.c` / `profession_skill.c` | 6 | 2 | 8 |
| **合计** | **139** | **27** | **166** |

★ **只有 2 个入口 ⇒ 替换为确定性序列是机械改造,不是重新设计。**

### 8.3 ★ 三类必须特殊处理的随机点

| 类型 | 说明 |
|---|---|
| **① 空推序列** | `BATTLE_Loop` 开头的裸 `rand();` —— **不消费结果,只推进序列**。重放时省略则后续全部错位 |
| **② 取模型** | 27 处裸 `rand()%N` 不经 `RAND` 宏 ⇒ **分布与 `RAND` 不同**(取模有偏),须分别实现 |
| **③ 浮点边界** | 上界是浮点表达式,取整时机影响结果 |
